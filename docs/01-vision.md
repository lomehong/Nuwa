# 01 · 愿景与定位

状态：已确认（2026-10-15）

## 愿景

把我们自己开发、自己运营的各个系统，变成"会自我愈合"的系统：运行时出现的故障，不再靠人肉翻日志、人肉改码、人肉提 PR，而是由一个专职的修复 Agent 完成从"发现问题"到"补丁合入"的全链路。

## 产品定义

**Nuwa 是一个问题单驱动的自动修复 Agent**：

1. **观测**：各系统内的采集 SDK（青鸟）持续收集运行时问题信号（异常、panic、错误日志、失败自检等）
2. **聚合**：信号被归一化为指纹，聚合成问题单——同指纹只更新计数与最近现场，不重复触发
3. **修复**：问题单触发服务端 Agent 运行器（基于 pi-rust 裁剪版），在目标仓库上定位、复现、修改、验证
4. **交付**：验证通过后**直接开 PR**（非 draft），CI 与仓库所有者是最终闸门

## 设计原则

- **现场永远只采集，修复恒在服务端**：生产现场通常只有构建产物没有源码，也不应承担 LLM 密钥与 agent 运行时的安全面；修复集中一处，预算、审计、升级只有一份
- **语言无关**：agent 修复任何语言的仓库；语言差异全部推到外围——采集层按语言长 parser，运行器按语言备工具链
- **小而专**：不做通用聊天 agent，不做交互式 TUI 产品；只做"问题单进、PR 出"这一条流水线
- **护栏优先**：自主开 PR 的前提是分支隔离、频控/预算、CI 闸门、禁改路径、复现验证证据五件套缺一不可

## 边界（不做什么）

- 不做通用对话助手 / 交互式编码助手
- 不做监控指标采集与告警路由（那是既有可观测性设施的事；Nuwa 只消费"问题信号"）
- 不做面向第三方的 SaaS——只服务所有者本人的私有系统群
- 不在现场生产进程内运行 LLM 循环或 shell 执行能力

## 成功标准（草案，待量化）

- 问题从"首次出现"到"PR 就绪"全自动完成，无人值守
- 误报 PR 率（CI 拒绝或被撤回的比例）可控在可接受阈值内
- 同一指纹不重复触发、不重复修
- 新接入一个系统：只需装采集 SDK + 放仓库指令文件 + 准备对应工具链 runner，agent 本体零改动
